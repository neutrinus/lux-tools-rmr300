## System Architecture

```
┌──────────────────────────────────────────────────────────────────────┐
│ Display Board (SNK_DISPLAY_CP_V11)                                   │
│  ESP32-WROOM-32UE: buttons START/HOME/OK, 7-segment display, buzzer, │
│  rain sensor (J4), WiFi/BT, cloud MQTT                               │
└─────────────┬────────────────────────────────────────────────────────┘
              │ J8 ribbon cable
              │ UART 230400 8N1, JSON frames &{json}<CRC8>#
┌─────────────▼────────────────────────────────────────────────────────┐
│ Main Board                                                           │
│  U13 (GD32F305) — main MCU                                           │
│   • Bootloader 0x08000000–0x08017fff: USB host/device, IAP, UART OTA │
│   • App from 0x08018000: motors, navigation, PIN, settings, logs     │
│   USART0  dpport  ←→ ESP32 (display board)                           │
│   USART1  bdport  ←→ U16 (GD32F303, border wire / lift sensors)      │

│   USBFS (PA11/PA12) ←→ J6 USB-A socket, bootloader only              │
│                                                                      │
│  W25Q64JVSIQ SPI NOR (8 MB): EasyFlash env (PIN, settings, config),  │
```

## 1. Ports

| Port | Peripheral | Base | Connects to |
|---|---|---|---|
| `dpport` | USART0 | `0x40013800` | ESP32 (J8), 230400 |
| `bdport` | USART1 | `0x40004400` | U16 `mport` |
| `ledport` | UART3 | `0x40004C00` | LED/ultrasonic board (optional, `lboard_en`) |

## 2. PIN Code — Storage and Verification

The PIN is a **4-digit** number, key `pwd` (uint32 LE) in the EasyFlash env on the
external SPI NOR. The app loads it at `08060858` into the RAM cache at
`0x2000027C` and saves it at `0807c96e`.

Verification (JSON over the J8 UART, see [`PROTOCOLS.md`](../../PROTOCOLS.md)):

1. The user enters the digits on the display board.
2. ESP32 → U13: `0x41000005 {"pwd":1234}`.
3. U13 compares with the cached `pwd` and answers `0x41000020` / `0x33000021` with `result`.
4. The ESP shows the unlocked or locked state.

### ESP32 NVS keys

| NVS key | Value | Meaning |
|---------|-------|---------|
| `robot_password` | `88888888` | WiFi/MQTT password, **NOT the PIN** |
| `robot_ssid` | `cy-public` | WiFi network name |
| `wifi_passwd` | `88888888` | Same WiFi password |
| `robot_name` | `MyMower` | Device name |
| `robot_sn` | `2312CGF250600035167` | Serial number |
| `iot_mqtt_uri` | `mqtt://server.sk-robot.com` | MQTT broker |

The ESP32 checks the password for WiFi/MQTT (`Check password succeeded/failed`).
The 4-digit PIN is checked by U13.

## 3. USB — Pendrive and PC

Only the U13 bootloader has USB code, so the J6 socket is used only at power-on.
The bootloader picks host (pendrive) or device (PC custom HID, VID `0x28E9`,
PID `0x0567`) mode from env `ota` / `cfg_rst` and the PB2 input (`080043ec`,
`08002f18`).

In host mode it scans the stick root in this order (`08003544`); files of size 0 are
skipped:

| File | Effect |
|---|---|
| `FORMATFLASH.json` | Chip erase of the external SPI NOR (`08001fa0`, command `0xC7`). Wipes the whole env: PIN, settings, product config, log, staging. Name loaded by `adr` at `0800359e` |
| `env_config*.json` | Version info + product config into env `cfgstr`, applied by the app on next start |
| `env_read.json` | Opened and reported to the display only |
| `SNK_MB_*.bin`, `SNK_BB_*.bin`, `SNK_DB*_*.bin`, `btl_MB_*.bin` / `SNK_MBTL_*.bin`, `SNK_LB_*.bin` | IAP (`0800303c`): copied into the SPI NOR staging area, then programmed by the "load app" step (`08007e18`) into U13 or sent to the other board over UART |

With no firmware file and a valid RTC it writes `log_yyyymmdd_hhmmss.html` (`08003cdc`).

### Bootloader main loop

`main` at `0800e800`:

```
Init:
  08004238  peripherals
  08008948  USB
  0800a6d8  env
  0800cf04  keys
  080024c4  ADC
  08007b78  wait for display board, 08007c68(0)
  080043ec  mode select (host/device/UART OTA/app)

Loop over flag word *0x20000018:
  bit 0          08012930  USB host core state machine
  bit 2          08003e0c  apply env_config*.json
  bit 11         08002fc0  env_read.json
  mask 0xd380    0800303c  IAP: copy SNK_*.bin from the stick to SPI NOR
  bit 1          08003cdc  save log to the stick
  bit 4 & bit 6  08007e18  "load app": program staged images, jump to app
  bit 13         08001370  OTA over UART
```

## 4. BMS Battery Strings

**The battery pack has its own smart BMS** with digital communication to U13.
See [BATTERY.md](BATTERY.md) for full details.

### Pack definitions in firmware

| String | Meaning |
|--------|---------|
| `5S1P_SUMSANG_20R` | 5S1P Samsung 20R (2000mAh) |
| `5S1P_SUMSANG_25R` | 5S1P Samsung 25R (2500mAh) |
| `5S1P_SUMSANG_29E` | 5S1P Samsung 29E (2900mAh) |
| `5S1P_SONY_VTC4` | 5S1P Sony VTC4 (2100mAh) |
| `5S2P_SONY_VTC4` | 5S2P Sony VTC4 (4200mAh) |
| `5S1P_EVE_2000` | 5S1P EVE 2000mAh |

### BMS log sample

```
I/bms ... 5S1P_SONY_VTC4, id=xxxxxxxxx, voltage=20234, ocv=20234, percent=100,
         temp=16degree, charging times=113, discharge times=123, health=0
```

### Communication protocol (partially known)

- Two drivers: `driver_battery_snk_v1.c` and `v2.c`
- CRC-checked commands: `battery connect failed, crc value=%d, receive crc=%d`
- Periodic polling: `send_battery_state_loop`
- Physical layer likely UART or I2C on the two data pins of J5 (see [BATTERY.md](BATTERY.md))

### Battery mods

The mower does **not** enforce a software runtime limit on capacity.
Larger packs (e.g. 5S2P or custom-built) work without firmware modification,
provided the original BMS is retained (or a compatible one is used).

## 5. User Settings and PIN Logic

From U13 firmware strings (module `service_user_set.c`). All of it lives in the env on
the SPI NOR (§6).

| Category | Keys / Strings | Description |
|----------|----------------|-------------|
| **PIN** | `pwd`, `pwd_en`, `pwd_rst`, `usr_pwd_en` | Password, enable flag, reset flag |
| **Schedule** | `schedule`, `simple schedule` | Mowing schedule |
| **Calibration** | `battery calibrate`, `rtc calibration` | Battery and RTC calibration |
| **User** | `user_name`, `language`, `cut area` | Name, language, mowing area |
| **Counters** | `work length`, `power on minutes` | Hours of operation |

### PIN functions (from strings)

| Function | Code string |
|----------|-------------|
| Verify PIN | `compare pwd correct` / `compare pwd uncorrect=%d` |
| Set PIN | `set pwd success` / `set pwd failed` |
| Change PIN | `set pwd old failed, because input old password error` |
| Reset PIN | `reset pwd success` / `reset pwd failed` |
| Lock after failures | `compare pwd uncorrect=%d overtimes, reset and lock` |
| Enable/disable | `set user enable password failed=%d` |
| Load PIN | `load user password failed` |

### Rate limiting

The firmware has brute-force protection:
```
"compare pwd uncorrect=%d overtimes, reset and lock"
```
After exceeding the limit of failed attempts, the system **locks** ("reset and lock").
The attempt limit (parameter `%d`) is unknown but typically 3-5 attempts.

### PIN reset methods

1. **Old PIN** → `set pwd old failed, because input old password error` (requires old PIN)
2. **pwd_rst** → remote reset command (likely from the app)
3. **FORMATFLASH.json** (non-empty) on a stick in J6 → SPI NOR chip erase, the whole env goes
4. **RAM read via SWD** — read PIN from `0x2000027C`

## 6. Env System (Key-Value Store)

U13 uses EasyFlash (`ef_port.c`, SFUD driver) on the external SPI NOR
(Winbond W25Q64JVSIQ, 8 MB). The bootloader and the app share the same env.

| Operation | Function | Description |
|-----------|----------|-------------|
| Read | `FUN_0800aa6c(key, buf, size)` | Read parameter from env |
| Write | `FUN_0800ae28(key, buf, size)` | Write parameter to env |
| Delete | `FUN_0800a84c(key, 0, 1)` | Delete parameter |

**Stored parameters (firmware versions, config):**
- `MB_VER`, `mb_sv`, `MB_BVER`, `MB_SIZE`, `MB_BRF` — Main Board
- `BB_VER`, `bb_sv`, `BB_BVER`, `BB_SIZE`, `BB_BRF` — Boundary Board
- `DB_VER`, `db_sv`, `DB_BVER`, `DB_SIZE`, `DB_BRF` — Display Board
- `LB_VER`, `lb_sv`, `LB_BVER`, `LB_SIZE`, `LB_BRF` — LED Board
- `BTL_VER`, `BTL_BVER`, `BTL_SIZE`, `BTL_BRF` — Bootloader
- `pdt_ver`, `ota_date` — Product version, OTA date
- `cfgupdate`, `cfgstr` — Config update
- `cfg_rst` — Config reset (0xa5a5 two-step reset)
- `ult_cfg`, `led_cfg` — Sensor and LED config
- `pwd`, `usr_pwd_en`, `user_name`, `language`, schedule, statistics — user settings (§5)

## 7. Firmware Update (two paths)

### Via USB (pendrive)
- `SNK_MB_*.bin` etc. on a FAT32 stick in J6, read by the bootloader at power-on
- Images are staged in SPI NOR, then programmed by the bootloader ("load app")
- Supports: MB, BB, DB, DBL, DBS, DBH, LB, BTL

### Via UART
- Bootloader UART OTA mode, selected by env `ota` = 1 or 5 (`08001370`: "get ota info", "write firmware fail")
- Packet: `[2 bytes length LE] [data] [1 byte XOR checksum]` (`08008cb8`)
- 7 commands: GET OTA INFO, DOWNLOAD, SET OTA MODE, SET VER, RETURN, SET FIRMWARE NUMBER, SET BAUDRATE
- Variable baudrate: 230400 → 460800 → 921600

## 8. Security Assessment — PIN Recovery

| Method | Possible? | Notes |
|--------|-----------|-------|
| **KV cache in RAM (SWD)** | ✅ YES | PIN in RAM @ `0x2000027C` — just dump RAM |
| **USB pendrive (FORMATFLASH.json)** | ✅ YES | Non-empty file; erases the whole SPI NOR env — PIN, settings and product config |
| **Read the SPI NOR** | ✅ likely | `pwd` is in the EasyFlash env; not tried |
| **Reset via app (pwd_rst)** | ❓ UNKNOWN | If the app has a PIN reset command |
| **New firmware (IAP with SNK_*.bin)** | ❌ NO | IAP does not clear the env |
| **Brute-force via display** | ❌ NO | Rate limiting — lockout after X attempts |
| **From ESP32** | ❌ NO | ESP32 only stores WiFi password |
| **From U13 flash** | ❌ NO | PIN is in the SPI NOR env, not in U13 flash |
| **U22** | ❌ NO | PIN is not stored there |

### Recommended PIN reset method (if forgotten)

1. **RAM read via SWD** — dump U13 RAM and read PIN from `0x2000027C` (our method). Keeps all settings.
2. **Factory reset via USB** — non-empty `FORMATFLASH.json` on a FAT32 stick (≤16 GB) in J6, power on.
   Also wipes the product config, which may need restoring with `env_config*.json`.

### Security notes

- PIN is cached in RAM at a fixed address (`0x2000027C`) — anyone with SWD access can read it
- The bootloader accepts `FORMATFLASH.json` from any stick in J6 — physical access wipes the env
- The env on the SPI NOR has no encryption
- Rate limiting is only software (in U13) — can be bypassed
